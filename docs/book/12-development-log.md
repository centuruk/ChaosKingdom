# 개발 기록 — 설계와 제작을 함께 남기기

## 2026년 10월 1일: 빈 폴더에서 첫 플레이까지

출발 폴더는 비어 있었다. 기존 프로젝트 규약과 코드를 탐색했으며 적용할 상위 AGENTS.md도 없었다. 장수제·지역 전략·소규모 지휘 전투·AI 생성 캠페인을 핵심으로 범위를 정했다. 작업 중 설계와 제작 과정을 책으로 편찬할 원고를 함께 작성하라는 요구가 추가되었다.

먼저 데이터 모델, JSON 콘텐츠, 시드 기반 세계 생성, 세계 검증을 만들었다. 이후 장수 효용 AI, 전략 턴, 경제·외교·승진·귀순·포로·세력 붕괴, 부대 전술 계산기를 연결했다. 게임 창 없이 24주의 캠페인을 생성해 200명과 50지역 계약과 실제 전투 사건을 확인했다.

다음에는 PyGame의 제목·캠페인·장수 선택·지도·열전·외교·연대기·전투 화면을 만들었다. 저장 파일의 난수 상태와 체크섬, 임시 파일 교체를 구현했다. GUI에서도 같은 엔진 명령을 쓰도록 연결하고 행동 후 자동 저장했다.

최초 자동 검증은 29개 통과였다. 실제 PNG 화면을 확인해 좁은 장수 프로필의 설명이 기력 표시와 겹치는 문제를 고쳤다. 연습 전투는 서로 다른 장수들이 부대를 지휘하도록 편성을 바꾸었다. 전투 결과의 중복 반영 방지도 추가했다.

다섯 시드로 240주를 진행한 초기 보고서에서 마지막 행동의 교류 편중을 발견했다. 친밀도 자체가 교류 필요를 높이던 수식을 포화에 따른 필요 감소로 바꿨다. 성주 계급 전체의 이동을 막던 조건은 실제 지역 관리자와 군주에게만 적용하도록 수정했다. 수정 전·후 보고서를 각각 보관한다.

원고는 요구·세계·구조·AI·전략·전투·캠페인·화면·저장과 검증·제작 도구·실습으로 나눴다. 최종 검증, 빌드와 원고 편찬 결과는 별도의 검증 기록에서 관리한다.

회귀 검증에서는 35개 테스트가 10.21초에 통과했다. 관계 포화, 사건 누적 계수, 조약을 존중하는 개전 건의, 군주 방침, 후방 우회 경유점, 플레이어 전투와 과업, 전투 중복 결산 거부를 추가 검증했다. Mac 빌드의 첫 시도는 사용자 라이브러리의 PyInstaller 캐시 폴더에 쓸 권한이 없어 중단되었다. 빌드 도구가 프로젝트 안의 캐시 폴더를 사용하도록 바꾸고 다시 빌드했다.

## 같은 날: 베타 확장과 이미지 제작

추가 요구는 클로즈드 베타 수준, 에이전트 구성과 AI 활용 방향의 원고, GPT Image로 만든 UI·초상·지도·배경, 지역별 전장과 편집기였다. 실제 제작은 한 주 개발 에이전트가 수행했다. 설계·시뮬레이션·전투·화면·미술·검증·원고의 일곱 역할은 재사용할 입력과 완료 기준으로 문서화했으며, 별도 에이전트 실행 이력으로 기록하지 않았다.

GPT Image Generator를 여덟 번 호출해 제목 배경, 세계지도, UI 장식, 지형 아틀라스와 네 장의 초상 아틀라스를 제작했다. 원본과 프롬프트 출처를 보존하고 200명에게 서로 다른 초상 주소를 부여했다. 첫 단순 순번 배치는 이름의 성별 표현과 초상의 인상이 어긋났고, 일부 아틀라스는 요청한 열 수와 실제 열 수가 달랐다. 이미지를 직접 확인한 뒤 열 범위와 장수 주소를 수정했다. 200개의 초상이 있다는 검증과 모든 초상이 전문 미술 감수를 받았다는 주장은 다르다.

지역 지형을 시드와 독립된 콘텐츠로 고정하고 50개의 서로 다른 타일 전장을 만들었다. 경로·시야·엄폐·중앙 거점을 전투에 연결했다. 편집기에는 칠하기와 출진·거점 이동, 실행 취소와 다시 하기, 연결 검증, 사용자 폴더 저장, 원본 복원과 시험 전투를 넣었다. 편집기의 시험 전투는 캠페인을 바꾸지 않고 편집 화면으로 돌아온다.

방어전 대기와 수비측 지휘, 전투 중간 저장과 백업, 역사 기반 개인 과업 두 개, 96주 연대기 결말과 이어하기, 로컬 제보와 복원 도구를 추가했다. 베타 검증의 첫 확장 실행에서 우회 명령 회귀가 발견됐다. 자동 전술 판단이 명령 직후 덮어써 경유점이 사라졌다. 명시한 명령 뒤 8초 동안 판단을 미루게 수정하고 회귀 검사를 통과했다. 실제 Mac 편집기 시험에서는 전장 이름은 산악 지역인데 부제가 임시 연습 세계의 강 지형을 읽는 표시 오류를 발견했다. 전투 지형 표시는 실제 전장 파일을 읽게 바꿨다.

검증은 전체 자동 검사, 50개 지역 전투, 세 시드의 480주 역사, 기사·재야·군주의 96주 행동 흐름을 포함했다. 화면을 다시 촬영하고 Mac 앱을 다시 빌드했다. 정확한 최종 수와 소요 시간, 압축 해제 실행과 플랫폼 미확인은 `docs/evidence/verification.md`에 남긴다. 에이전트·AI·이미지·전장 편집기·베타 운용 원고는 13~17장에 추가했다.

네이티브 전투를 25초 진행해 산악 통로로 부대가 모이는 장면을 확인했다. 초기 배치 화면에서는 드러나지 않던 부대 숫자 겹침이 생겼다. 이동과 전투 좌표는 유지하고, 겹치는 상태 표시를 주변의 빈 행으로 옮겨 부대까지 안내선을 그렸다. 아군·적군 번호도 붙였고 중앙 거점 확보 시간은 사용자의 편 순서로 표시했다. 전투 시작 화면 한 장으로 진행 중 가독성까지 검증했다고 말할 수 없는 이유였다.

## 이후 기록의 형식

다음 작업부터는 요구, 선택, 변경한 파일, 사용한 입력, 실제 결과, 남은 문제, 원고에 반영한 장을 한 단위로 기록한다. 실패한 시도는 결과에 영향을 주었을 때만 남긴다. 명령을 전부 복사하는 로그보다 다음 개발자가 판단을 재현할 수 있는 기록을 우선한다.

기능을 약속하는 문장에는 목표를, 완료를 말하는 문장에는 소스와 검증 근거를 붙인다. 개발판의 한계를 출판용 문장으로 감추지 않는다. 이 기록 원칙은 세계의 연대기와도 닮았다. 행동이 먼저이고, 그 행동에서 설명 가능한 역사가 나와야 한다.

## 2026년 10월 1일: 코드 구조를 설명하고 평면 지형을 다듬다

추가 요구는 실제 에이전트 구성과 OOP 코드 구조를 책에 설명하는 것, 그리고 산·지면·강이 자연스러운 전장을 만드는 것이었다. 사용자는 단차를 요구한 것이 아니라고 명확히 설명했다. 높이 규칙을 추가하지 않고 평면 재질과 지형 경계·배치 문제로 범위를 정했다.

3장에 실제 클래스 책임, 합성, dataclass, ID 연결, 명령 흐름과 저장 복원을 설명했다. 화면 없이 실행하는 예제를 추가하고 실제 실행했다. 13장에는 주 개발 에이전트 1개와 역할 계약 7개, 도구와 장수 AI의 차이, 작업 입력·산출물·검증과 후속 분담안을 적었다. 별도 보조 에이전트를 실행했다고 기록하지 않았다.

GPT Image Generator로 새 4×2 평면 재질 시트를 생성했다. 전장 렌더러는 연결된 재질을 합성하고, 기본 전장 생성기는 난수의 개별 점 대신 숲과 바위 덩어리를 만들게 바꿨다. 격자를 보기 상태로 전환했고 기존 h 코드의 이름은 바위 지대로 바꿨다. 원본 PNG·사용자 편집본·저장 전투의 지형은 보존했다.

화면을 확인한 뒤 강과 숲 모서리의 각진 부분을 표시 마스크 필터로 한 번 더 다듬었다. 이전 베타의 실제 전장 파일을 추출해 저장 호환 검사 자료로 남겼다. 전체 자동 검사, 연결 검사, 지역 전투·역사 실험을 다시 수행하고 현재 결과로 검증 기록과 배포 후보를 갱신한다. 이전 관측값은 별도 보고서로 보존해 변경 후 수치와 혼동하지 않게 했다.

## 같은 날: 캠페인을 실제 창에서 플레이하다

사용자의 요청에 따라 Mac 앱을 실제로 열고 ‘왕관 없는 새벽’의 아델 발렌을 선택했다. 시드 742로 생성된 24주의 역사에서 시작해 내정, 벨라 발렌과의 교류, 새벽관 이동, 늙은 제분소 진군과 직접 지휘, 점령지 순찰을 수행했다. 최종 저장은 29주이며 직접 플레이한 전략 시간은 5주다. 이 기록의 조작자는 Codex 주 개발 에이전트이고 외부 플레이테스터는 참여하지 않았다.

늙은 제분소는 다리 두 곳이 있는 강 전장이었다. 아군 820명으로 적군 1000명과 싸웠다. 주력을 거점으로 보내고 보병에게 방어를 지시했으며 기병과 궁병으로 적 궁병을 집중 공격했다. 손실이 큰 기병을 회수한 뒤 창병과 궁병으로 적 기병을 상대했다. 경과 표시 164초에 ‘적 부대 와해’로 승리했고 손실은 아군 219명, 적군 883명이었다. 왕국 화면으로 돌아가 영지 소유 변경, 장수 이동과 첫 승전 과업 완료를 확인했다.

전투 78초에 일시정지하고 앱을 종료·재실행했다. ‘저장한 이야기’를 눌러 같은 경과 시간, 아군 613명·적군 509명, 부대 위치와 거점 확보 표시 56초가 복원되는 모습을 확인했다. 속도는 기본 1배로 돌아갔으며 전투는 일시정지 상태에서 재개를 기다렸다. 최종 저장은 읽기 전용으로 체크섬과 세계 구조를 검증했다. 장수 200명, 성 20개, 거점 30개를 유지했고 진행 중 전투는 남지 않았다.

실제 조작은 자동 검사의 통과만으로 알 수 없는 문제를 드러냈다. 이름표를 분리해도 교전 부대의 몸체가 겹쳐 위치를 읽기 어려웠다. 수비 부대가 다리와 거점 위협에 함께 대응하지 못해 적을 차례로 상대하는 흐름도 나타났다. 번영 100인 수도에 ‘재건’ 과업을 붙이거나 이미 목표 친밀도를 넘은 관계 과업을 첫 행동 후 완료시키는 생성 규칙은 도전의 맥락이 약했다. 현재 명령·공격 대상·승리 조건 안내도 보완할 필요가 있다.

따라서 이번 결과는 캠페인과 전투·점령·저장을 연결해 플레이할 수 있다는 근거로 기록한다. 한 번의 승전을 재미와 난이도의 완성 판정으로 바꾸지 않는다. 이 세션에서는 게임 코드와 배포 압축 파일을 변경하지 않았으며 발견 사항은 후속 개선 대상으로 남겼다. 실제 플레이 경로와 수치는 [플레이 기록](../evidence/native-play-2026-10-01.md)에 보관한다. 방어전, 패전, 전체 96주 결말과 Windows 실행은 이번 플레이의 검증 범위가 아니다.

## 2026-10-01 — 아이소 전투와 천하통일, 제작 지침의 출처

실제 캠페인 플레이에서 부대 몸체 겹침, 수비 부대의 초기 대기, 이미 깊은 관계로 자동 완료되는 과업, 건강한 영지를 재건이라 부르는 문구와 거점 승리 조건의 혼동을 발견했다. 후속 요청은 이미지 성벽·다리, 아이소 전투와 천하통일이었다. 높이차를 요구하지 않았다는 설명도 유지했다.

투영과 역변환을 `IsometricProjection`에 모아 전투와 편집기가 같은 좌표를 사용하게 했다. 평면 재질을 회전·압축하고 투명 건축물과 부대를 깊이 순으로 그렸다. 집단 이동은 목적지를 분산하고 활동 부대는 제한된 거리로 비켜 선다. 수비 AI는 거점 주변으로 재배치한다. 신규 과업은 현재 지역·관계 상태를 검사한다. 통일은 실제 소유권 50개로 판정하고 96주는 중간 기록으로 바꿨다. 기존 과업과 지형 스냅샷은 유지한다.

GPT Image Generator를 실제 두 번 호출해 4열·2행 건축물·부대 시트를 만들었다. 원본·프로젝트 사본·프롬프트·SHA-256을 보존했다. 성벽 방향 중 하나는 런타임 좌우 반전으로 맞췄다. 부대 그림에는 요청과 달리 작은 바닥 조각이 들어갔으며 이 한계도 기록했다.

첫 전체 전장 검사에서 s01의 59.4초에 창병이 성문 모서리의 막힌 칸 (25,8)에 들어갔다. 부대 회피로 경로 중심에서 비켜 난 뒤 다음 경로 지점으로 직진한 것이 원인이었다. 선분이 건너는 모든 격자 구간을 검사하고, 막힌 경우 현재 칸 중심으로 돌아오게 수정했다. 해당 실제 좌표를 회귀 검사에 남겼으며 50전장 검사를 다시 통과했다. `.venv/bin/pytest` 직접 실행은 프로젝트 import 경로 때문에 수집에 실패했으므로 `.venv/bin/python -m pytest`로 실행했다.

최종 70개 검사 통과는 58.70초, 50개 전투·세 시드 480주·세 역할 96주 검사는 59.168초였다. 고정 편성에서 공격 35승·수비 15승, 최장 180.2초를 관측했다. 이전 28승·22승과 비교할 때 수비 AI뿐 아니라 성곽·성문과 부대 이동도 바뀌었다는 조건을 함께 남긴다. 세 역할 모두 중간 연대기를 기록하고 최종 outcome은 없었다. 이것을 장편 통일 캠페인 완주로 쓰지 않는다.

사용자의 추가 요구에 따라 `AGENTS.md` 외 스킬·도구 기록을 명세와 13장에 추가했다. `imagegen`은 실제 적용·도구 실행, `superdesign`은 독립 자산 경로 지침 참고이며 CLI와 캔버스는 미실행이다. 실제 개발 에이전트는 1개이고 별도 보조 에이전트 실행은 없다. 역할 계약을 실행 이력으로 바꾸지 않는다.

새 Mac 앱과 배포 ZIP 검사는 성공했고 실제 29주 저장의 사본도 새 실행 파일에서 복원·렌더했다. 원본 저장은 변경하지 않았다. 새 창을 열어 입력을 확인하려던 시도는 Mac 잠금으로 중단됐다. 사용자에게 수동 해제를 요청했고 네이티브 입력 검증은 미확인으로 남긴다. 원고 브라우저에서는 18장·그림 10개·13장 스킬 명세와 목차 이동, 가로 넘침 없음을 확인했다.


## 2026-10-01 — 사용자의 알파 제보를 실제 화면에서 재현하다

사용자는 플레이 중 알파가 제대로 적용되지 않은 것 같다고 제보했다. Mac 메뉴 장식 뒤의 검은 사각형을 실제 창에서 관측했다. 원본 알파와 배포 사본 해시, dummy 렌더 결과는 정상이었다. Cocoa에서 같은 배포 실행 파일을 렌더하자 결함이 재현됐다. 기본 캔버스가 디스플레이의 알파 마스크를 상속하면서 합성 플래그를 갖지 않는 차이를 찾아, 32비트 `SRCALPHA` 캔버스를 명시했다. 원본 이미지와 게임 상태 모델은 유지했다.

조사 도중 venv에 Pillow가 없어 pygame으로 픽셀을 검사했다. 제한된 실행 환경에서 Cocoa 테스트는 종료 코드 134였지만, 실제 디스플레이 접근을 허용한 같은 검사에서는 재현됐다. 새 회귀 검사 삽입 위치가 기존 편집기 검사의 일부를 잘못 옮겨 세 NameError를 낸 오류도 바로잡았다. 이후 옛 캔버스 생성자를 메모리에서 복원한 검사는 세 화면의 알파 조건에서 예상대로 실패했고, 수정 후 전체 73개가 60.30초에 통과했다. 지도 50개의 연결 검사도 통과했다. 시뮬레이션은 변경하지 않아 이전 장기 전투·역사 실험 결과는 이전 버전의 기록으로 유지했다.

0.3.0-beta.2 Mac 앱을 다시 빌드했다. 실제 창의 메뉴 장식, 일시정지된 연습 전투의 부대·성벽, 발렌하임 편집기의 성곽과 늙은 제분소 편집기의 다리에서 검은 사각형이 사라짐을 확인했다. 편집본을 저장하거나 캠페인 주차를 진행하지 않았다. 최신 저장에는 에버홀드 전투가 있었고 74초 지점에서 일시정지 상태로 복원해 사용자가 이어서 플레이하도록 두었다. 이전 29주 캠페인 기록과 현재 사용자의 진행을 혼동하지 않는다.
