# 17장. 플레이 가능한 개발판에서 클로즈드 베타로

## 베타에 필요한 끝과 복구

기능을 연결한 개발판과 테스터가 반복해서 플레이하는 베타는 다른 요구를 가진다. 첫 연대기를 끝낼 수 있어야 하고, 도중에 중단해도 돌아올 수 있어야 하며, 문제가 생기면 제작자가 같은 상태를 볼 수 있어야 한다. 베타 확장의 중심은 지역 전장, 개인 과업, 방어 지휘, 전투 저장과 재현 자료였다.

장수를 선택하면 기본 과업 세 개와 역사 기반 과업 두 개가 생긴다. 0.3 베타의 최종 목표는 성 20개·거점 30개를 모두 다스리는 천하통일이다. 96주마다 명성·승전·과업을 중간 연대기에 기록하며 캠페인은 자동으로 계속된다. 개인 성장의 기록과 최종 승리를 구분한다.

## 방어 지휘의 처리 순서

주간 AI의 국경 출정에서 현재 장수가 머무는 아군 영지가 공격받고 지휘 가능한 상태라면 방어전을 대기 상태로 만든다. 다른 주간 행동과 사건 처리를 끝내고 사용자의 지휘 화면으로 넘어간다. 전투 대기 중에는 새 주를 시작하지 않는다. 방어전 결산은 이미 진행한 주를 한 번 더 증가시키지 않는다.

이 구현은 주간 함수의 중간 장수 인덱스를 저장하는 방식보다 작은 상태를 필요로 한다. 전투의 두 영지는 그 주의 다른 출정에서 사용하지 않는다. 현재 주를 마친 뒤 전투 결과만 기다린다는 계약을 지키면 저장 시 진행 중인 장수 순서를 복원할 필요가 없다. 방어 완료 시 과업과 결말 조건은 다시 평가한다.

사용자의 편은 공격전에서는 0, 방어전에서는 1이다. 화면의 아군 색과 부대 선택, 격려, 철수, 승패 표시가 이 값을 읽는다. 공격군을 항상 아군이라고 쓰면 방어전에 들어갔을 때 UI와 규칙이 어긋난다. 실제 테스트는 수비측 이동 명령과 철수의 승자까지 확인한다.

## 전투도 저장한다

전략 저장은 원자적 교체와 세계 체크섬을 유지한다. 베타는 여기에 전투 데이터와 별도 체크섬을 추가한다. 부대 병력·사기·명령·경로, 전투 시간과 누적 시간, 격려 재사용 시간, 중앙 거점 확보, 지역 지형, 사용자의 편을 저장한다. 예전의 전투가 없는 저장 파일도 읽는다.

전투에서는 10초마다 자동 저장하고 F5로 수동 저장할 수 있다. 게임을 종료할 때도 현재 상태를 남긴다. 불러온 전투는 일시정지 상태로 시작해 사용자가 지휘 상태를 확인하게 한다. 직전의 정상 저장은 백업 파일로 보존한다. 손상된 현재 파일을 정상 백업 위에 복사하지 않도록 이전 저장의 검증을 먼저 한다.

저장 후 같은 입력으로 진행했을 때 전투 데이터가 동일한지 자동 검사한다. 화면이 비슷해 보인다는 확인보다 시간, 부대, 병력, 사기와 경로를 함께 비교하는 편이 강하다. 결과가 이미 반영된 전투는 다시 적용하지 않는다.

## 제보를 실행 가능한 자료로 만든다

R키나 메뉴의 문제 제보 저장은 로컬 ZIP을 만든다. 사용자 계정이나 컴퓨터 이름, 전체 환경변수를 수집하지 않는다. 게임 버전·Python·PyGame·운영체제 종류·아키텍처, 세계 상태와 체크섬, 최근 명령, 현재 전투, 50개 전장을 포함한다. 자동 업로드는 없다. 테스터가 전달할 파일을 직접 고를 수 있다.

`tools/replay_report.py`는 이 ZIP을 별도 폴더에 복원한다. 기존 캠페인을 덮어쓰지 않고 그 폴더를 게임의 사용자 폴더로 지정하면 같은 세계와 전장을 불러올 수 있다. 예상하지 못한 예외는 별도의 로컬 진단 파일에 남긴다. 진단 파일의 경로와 오류 메시지는 개발자가 재현의 출발점을 찾게 한다.

## 통과와 미확인을 구분한다

자동 검증은 50개 전장의 연결성과 실제 전투 종료, 480주 역사 실험, 기사·재야·군주 역할의 플레이 흐름, 전투 저장, 편집기 복원과 시험 전투를 다룬다. 실제 숫자와 운영체제는 `docs/evidence/verification.md`와 원본 로그를 기준으로 기록한다. 테스트가 통과했다고 사람이 재미를 확인했다고 쓰지 않는다.

지역 전투의 고정 실험은 공격 출진 820명·수비 700명에서 공격 승리 35회, 수비 승리 15회였다. 세 역할 실험은 내정·수련·순찰·징병·교류·휴식 및 임관을 반복했으며 스크립트의 수동 공격 성취도는 측정하지 않았다. 기사 흐름의 승전 1회는 대기 방어전을 자동 결산한 결과다. 관측 조건을 함께 써야 승률이나 결말이 전체 플레이의 균형을 보장한다는 오해를 줄일 수 있다.

macOS에서는 실행 파일을 직접 빌드하고 창과 입력을 확인한다. Windows는 실행 스크립트와 대상 OS에서 빌드하는 워크플로를 제공한다. 이 개발 환경에서 Windows 실행기를 실제로 실행하지 못했다면 그 칸은 미확인이다. 서명·공증과 외부 테스터의 플레이 평가도 별도 배포 단계다. 베타 후보의 코드 완성과 모든 플랫폼의 외부 배포 승인을 같은 상태로 표시하지 않는다.

## 테스터가 처음 확인할 흐름

첫 세션은 새 캠페인, 장수 선택, 내정과 교류, 과업 확인, 저장과 재시작으로 시작한다. 다음에는 공격 또는 방어 전투에서 지휘와 중간 저장을 시험한다. 마지막에는 전장 편집기로 다른 다리를 만들고 시험 전투를 돌린다. 흐름이 끊기거나 상태가 달라지면 제보 ZIP과 재현 순서를 남긴다.

베타의 목적은 결함의 부재를 선언하는 것이 아니라 실제 사용자의 선택으로 남은 결함과 지루한 규칙을 발견하는 데 있다. 이 책은 그 발견을 받을 수 있는 코드와 도구를 만드는 단계까지 기록한다.

## 새 후보의 실행 파일과 원고 확인

0.3 Mac arm64 실행 파일을 빌드하고 배포 ZIP에서 압축 해제해 지도·편집기·전투를 headless 모드로 확인했다. 기존 29주 캠페인의 사본도 새 실행기로 불러왔으며 주차·장수·영지·과업·난수와 사용자 원본 저장의 불변을 확인했다. 생성 원본 11개와 해시, 프레임워크 심볼릭 링크 91개, 실행 권한과 소스 묶음의 사용자 저장 제외도 검사했다.

새 앱의 네이티브 창 입력 검증은 Mac 화면 잠금 때문에 진행하지 못했다. 사용자에게 수동 해제를 요청했으며 이 후보의 실제 마우스·키보드 확인은 미확인이다. 이전 후보의 창 플레이와 새 실행기의 headless 검증을 혼동하지 않는다. 브라우저 원고는 18장·내장 그림 10개 로드와 13장 스킬 기록, 가로 넘침 없음과 목차 이동을 확인했다.


## 0.3.0-beta.2의 알파 수정 검증

사용자의 실제 Mac 창 제보를 계기로 PNG 합성 결함을 수정했다. 상세 원인은 8장, 조사와 실패 기록은 12장에 설명한다. 전체 검사는 73개가 60.30초에 통과했고, 전장 50개의 고유 배치와 연결도 유지했다. Cocoa 배포 실행 파일에서 메뉴·전투·편집기의 완성 프레임 알파는 모두 255였다. 실제 창에서 메뉴·연습 전투·성곽과 강 편집기의 이미지 합성을 확인했고 최신 저장의 에버홀드 전투 74초를 일시정지 상태로 불러왔다. 이는 이미지 합성과 마우스 화면 이동 확인이며 새 버전의 전투 완주나 키보드 검증 기록은 아니다.

이 수정은 화면 캔버스에 한정된다. 앞 표의 50전장 전투·480주 역사·역할 흐름 수치는 0.3.0-beta.1에서 수행한 실험이다. 알파 수정 버전에서 같은 실험을 새로 수행했다고 쓰지 않는다. 원본 PNG 11개와 저장 스키마는 유지했고 Mac 앱과 원고·소스 배포본을 0.3.0-beta.2로 갱신한다. Windows에서의 실제 실행은 여전히 확인 범위 밖이다.
