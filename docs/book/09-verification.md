# 9장. 저장, 실패, 검증

## 현재를 저장하는 것과 미래를 저장하는 것

화면에서 보이는 현재 영지와 장수만 저장하면 현재는 복원할 수 있다. 그러나 다음 주에 같은 행동이 발생한다는 보장은 없다. 난수의 현재 상태가 빠져 있기 때문이다. 저장 파일에는 세계 데이터와 난수 상태, 스키마 버전, 데이터 체크섬을 포함한다.

불러올 때 버전을 확인하고 체크섬을 검사한 뒤 데이터를 모델로 복원한다. JSON 목록으로 바뀐 난수 상태는 중첩 튜플로 복원해 `Random.setstate`에 전달한다. 이후 World.validate로 참조와 범위를 검사한다.

체크섬은 악의적인 변경을 막는 서명이 아니다. 파일 손상과 의도하지 않은 외부 변경을 탐지하는 장치다. 사람이 데이터를 수정한 뒤 체크섬을 다시 만들 수도 있다. 싱글플레이 개발 도구에서는 편집을 금지하는 것보다 깨진 상태를 알려주는 일이 중요하다.

## 저장하다가 중단되면

파일을 바로 덮어쓰는 중에 프로그램이 종료되면 기존 저장까지 잃을 수 있다. 그래서 같은 디렉터리에 임시 파일을 만들고 JSON을 기록한 뒤 flush와 fsync를 실행한다. 마지막에 os.replace로 교체한다. 기록이 끝나기 전에는 이전 파일을 유지하는 방식이다.

0.1에서는 전략 상태만 저장했다. 베타는 전장의 누산기·명령·목표·경로·결속·와해 상태와 전장 데이터를 별도 체크섬으로 저장한다. 전투를 불러오면 일시정지 상태로 시작한다. 전략 행동 뒤와 전투 10초마다 자동 저장하며 정상인 직전 파일은 백업으로 보존한다. 17장에서 저장 계약과 재현 도구를 설명한다.

## 검증의 층

첫째는 세계 계약이다. 200명·50지역·20성·30거점, 유효한 참조와 연결된 도로, 자원과 능력 범위를 확인한다. 둘째는 재현이다. 같은 시드의 세계와 역사를 비교하고 저장 후 다시 불러온 세계를 원본과 같은 기간 진행한다. 현재뿐 아니라 다음 12주의 최종 데이터 해시도 일치해야 한다.

셋째는 행동과 전투다. 거절된 명령이 아무 상태도 바꾸지 않는지, 부대 초기 병력 합이 상한을 지키는지, 전투가 180초 안팎에 끝나는지, 결과가 병력과 역사에 반영되는지 확인한다. 넷째는 UI 연결이다. 모든 화면이 실제로 그려지고 저장·불러오기와 연습 전투가 올바른 세계를 쓰는지 확인한다.

## 처음 실행한 결과

초기 검증에서 자동 테스트 29개가 28.06초에 통과했다. 네 시드의 생성 계약, 재현과 저장, 손상 파일 거부, 명령 부작용, AI 상태 변화, 전투, 다섯 시드의 240주 장기 실행, 화면과 모달 검증을 포함했다. 이후 회귀 검증의 최종 결과는 `docs/evidence/verification.md`에 기록한다. 이 최초 수치는 최초 실행에 대한 기록이며 최신 테스트 수를 대신하지 않는다.

화면은 SDL dummy 모드에서 PyGame으로 실제 렌더해 PNG로 저장하고 직접 확인했다. 마우스를 움직인 사람의 사용성 테스트와는 다르다. 버튼의 상태 전이와 논리 좌표 변환은 자동 검증으로, 가독성과 정보 겹침은 이미지 확인으로 나눠 확인했다.

## 실패도 입력과 결과를 남긴다

첫 의존성 선택은 문서에 표시된 pygame-ce 2.5.9였다. 그러나 실제 패키지 저장소에서는 그 버전의 배포본을 찾을 수 없었다. 사용 가능한 2.5.8을 확인해 프로젝트의 요구 버전을 바꾸고 가상환경에 설치했다. 문서의 최신 표기와 실제 설치 가능한 버전이 항상 같다는 가정을 버렸다.

네트워크가 제한된 기본 실행 환경에서는 처음 패키지 내려받기도 실패했다. 필요한 패키지를 프로젝트 가상환경에 설치하는 네트워크 실행 권한을 얻은 뒤 진행했다. 이 실패와 버전 문제를 섞어 설명하지 않는다. 앞의 것은 환경 접근 문제, 뒤의 것은 패키지 존재 여부 문제다.

## 밸런스는 테스트 통과와 다르다

최초 다섯 시드의 240주 결과에서는 마지막 행동이 교류인 장수가 137~152명이었다. 데이터가 유효하고 전쟁도 계속되었지만, 사회 행동이 과도하게 자신을 강화하는 경향이 보였다. 그래서 관계 포화에 따른 필요 감소와 실제 관리자 여부에 따른 이동 조건을 수정했다.

수정 전 보고서는 `balance-240-before-social.json`, 수정 후 보고서는 `balance-240.json`에 남긴다. 이 값은 240주 전체 행동 빈도가 아니라 **240주 시점 각 장수의 마지막 행동**이다. 의미를 정확히 붙이지 않으면 개선 정도를 과장할 수 있다.

상용 밸런스가 검증되었다고 말할 수는 없다. 사용자가 재밌다고 느끼는 전투와 인간관계는 실제 플레이로 판단해야 한다. 자동 검증은 그 실험을 안정적으로 수행할 수 있는 바탕이다.
